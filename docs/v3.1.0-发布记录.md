# v3.1.0 发布记录

> 日期：2026-05-30
> 主题：拖入式终端交互 + 三套入口统一

## 背景

此前双击平台脚本时，会优先处理脚本所在目录；找不到合规图片时再弹出文件夹选择器。这个流程要求用户理解“脚本要放在哪里”，也让 macOS 和 Windows 都依赖额外的 GUI 弹窗。

本版改为纯终端 TUI：启动脚本后显示标题、步骤、命名规则和拖入提示。用户把任意一张图片拖进终端并回车，工具会自动定位那张图片所在的文件夹，收集其中所有符合命名规则的 JPG/PNG，并在该文件夹生成 PPTX。

## 改动

1. **Python 无参数进入交互引导**：`python3 images_to_pptx.py` 现在会提示拖入图片或文件夹；保留传参用法作为高级模式。
2. **macOS 入口改为拖入式终端引导**：`图片转PPTX-macOS.command` 不再默认扫描脚本所在目录，也不再弹文件夹选择器。
3. **Windows 入口改为拖入式终端引导**：`图片转PPTX-Windows.cmd` 不再弹 WinForms 文件夹选择器或完成弹窗，输出集中在终端。
4. **拖入路径解析**：
   - macOS / zsh：用 zsh 词法分割和去引用处理 `/a/My\ Pics/01.jpg`、`"/a/My Pics/01.jpg"` 等输入。
   - Windows / PowerShell：优先读取双引号或单引号包裹的路径，否则取第一个空白分隔段。
   - Python：POSIX 平台使用 `shlex.split`，Windows 平台按引号优先解析。
5. **文件路径也可作为输入**：交互或高级传参时，如果输入是一张图片，会自动取它的父文件夹。
6. **空输入 / 无效路径循环提示**：不会直接退出；Ctrl+C 或 EOF 才退出。

## 本次改动的文件

- `images_to_pptx.py`：版本号 → 3.1.0；新增拖入式引导、跨平台路径解析、文件路径转父文件夹、无参数交互入口。
- `图片转PPTX-macOS.command`：版本号 → 3.1.0；新增终端引导与 zsh 路径解析；移除脚本目录兜底和 AppleScript 文件夹选择/弹窗。
- `图片转PPTX-Windows.cmd`：版本号 → 3.1.0；新增终端引导与 PowerShell 路径解析；移除 WinForms 文件夹选择/完成弹窗；设置 UTF-8 控制台编码。
- `README.md`：推荐用法改为“启动脚本 → 拖入图片/文件夹 → 回车”，新增 macOS / Windows 权限提醒。
- `CHANGELOG.md`：新增 `[3.1.0]` 条目。

## 兼容性说明

- 旧的“把脚本放进图片文件夹后双击”流程不再作为默认流程；现在双击后需要拖入一张图片或文件夹。
- Python 命令行参数保留；传入文件夹仍可直接生成，传入图片文件时会处理其父文件夹。
- macOS / Windows 平台脚本仍会在生成后尝试自动打开 PPTX。

## 验证

- `images_to_pptx.py`：`python3 -m py_compile` 通过；路径解析样例通过；用带空格的临时图片目录模拟 stdin 拖入并成功生成 PPTX。
- `图片转PPTX-macOS.command`：`zsh -n` 通过；用 macOS 反斜杠转义路径模拟拖入并成功生成 PPTX。
- 生成的 Python / macOS 两个 PPTX 均已通过 `unzip -t` 校验。
- `图片转PPTX-Windows.cmd`：本机无 `pwsh` / `powershell`，未实跑 Windows 双击流程；已做静态检查，确认 PowerShell 区块存在、here-string 成对、WinForms/MessageBox/FolderBrowserDialog 已移除、交互函数存在，且文件行尾统一为 CRLF。
